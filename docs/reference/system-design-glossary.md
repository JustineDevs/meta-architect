# System design glossary

Meta-Architect ships a bounded glossary for architecture conversations. It is a
shared vocabulary and selection aid, not proof that a style or pattern fits a
project. `$arch` must still connect every selected term to requirements,
constraints, trade-offs, and evidence.

The machine-readable catalog is [`data/system-design-glossary.json`](../../data/system-design-glossary.json).
It covers architecture styles, modeling vocabulary, distributed-systems
trade-offs, reliability concepts, security boundaries, and delivery concerns.

The catalog is intentionally explicit about its boundary. It is not a claim to
contain every term in software architecture. When a needed term is absent,
`$arch` must qualify it as an external concept, cite the source used, and avoid
treating the glossary definition as evidence.
